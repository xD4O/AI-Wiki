CHAPTER 15Part IV · Systems & Control

Deterministic Gates & Structured Control

The other side of orchestration — making the output of an LLM checkable, gated, and predictable. Constrained decoding at the token level, contracts at the tool level, formal verification at the aspirational level.

2023-04 Guidance (Microsoft) 2023-08 Outlines 2023-09 SGLang structured generation 2024-08 JSON Schema in OpenAI API 2024-2025 AlphaProof · Lean + LLM 2025-2026 structured decoding default in production
🧒 ELI5 — explain like I'm five

Asking an LLM "please return JSON" works most of the time. Most of the time is the problem — production systems break on the 1% that returns prose.

A deterministic gate is a rule the model is forced to follow at the token level. The simplest: "the next token must be one of {0,1,2,...,9}." Slightly fancier: "the output must match this JSON schema." Fanciest: "the output must be a Lean proof that type-checks against this theorem."

The gate doesn't make the model smarter. It makes the model's output parseable, which makes everything downstream — agents, tools, databases — actually safe to trust.

15.1 The Ungovernable-Output Problem

An LLM is a probability distribution over next tokens. There is no inherent guarantee that the distribution will produce parseable JSON, valid SQL, or a function call that matches your schema. "Asking nicely" produces good results 95-99% of the time. In production, that 1% costs more than every gain you ever made from prompt-tuning.

The 2023 fix was retry-on-parse-failure. The 2024-2026 fix is to make invalid output impossible to generate: at every decode step, mask the logits of tokens that would violate the constraint.

15.2 Constrained Decoding

The recipe is identical across implementations:

  1. Express your constraint as a finite-state machine (FSM) — possibly compiled from a regex, JSON Schema, or context-free grammar.
  2. At each decode step, the FSM tracks which characters/tokens are allowed next.
  3. Mask the LLM's logits to set disallowed tokens to \(-\infty\).
  4. Sample from the masked distribution. The output is guaranteed to be in-grammar.
Constrained decoding: a schema becomes an FSM, the FSM masks logits, the sampler emits guaranteed-valid output. Outlines, Guidance, SGLang all do this.

15.3 The Expressivity Ladder

LevelConstraintCostExamples
1RegexCheap"phone number", "ISO date", "uppercase ID"
2JSON SchemaCheap+API responses, structured extraction
3Context-free grammarModerateSQL, code, EBNF for any DSL
4Semantic / type-checkedExpensive"valid SQL against this schema", "callable Python"
5Formal proofAspirationalLean proof that type-checks; Z3-verifiable invariant

Each level rules out more output but takes more work to compile and check. Most production gates sit at levels 2-3.

15.4 Contracts Around Tool Calls

For agents (Ch 14), gates apply to which tool with what arguments. The pattern: define typed tool signatures, validate every proposed call against pre-conditions, refuse or ask for repair if invalid.

from pydantic import BaseModel, Field

class TransferRequest(BaseModel):
    from_account: str = Field(pattern=r"^ACC-\d{8}$")
    to_account:   str = Field(pattern=r"^ACC-\d{8}$")
    amount_cents: int = Field(gt=0, le=10_000_000)        # max $100K
    currency:     Literal["USD", "EUR", "GBP"]
    memo:         str = Field(max_length=120)

@tool(schema=TransferRequest)
def transfer(req: TransferRequest) -> str:
    if req.from_account == req.to_account:                # post-condition
        raise ValueError("self-transfer")
    return ledger.write(req)

The schema constrains what the LLM can say. The validator constrains what the system does. Two layers of gate, both deterministic.

15.5 Formal Methods ∩ LLMs

The aspirational end of the ladder. Two recent demonstrations:

  • AlphaProof / AlphaGeometry 2 (DeepMind 2024) — LLM proposes proof steps in Lean; the Lean type checker rejects invalid steps. Result: silver-medal performance at IMO 2024.
  • Z3-guided decoding — at each branch in code generation, an SMT solver checks whether the partial program can still be completed satisfying constraints; if not, backtrack.

The marriage of LLM (proposes) + checker (disposes) gives both creativity and soundness. As of April 2026 the technique is maturing for math, code, and contract-validation; it does not yet apply to open-ended language.

15.6 When Gates Hurt

Constraints are not free

Hard masking can hurt quality when the schema rules out the right answer. A grammar that forbids a needed field, a regex that excludes a valid Unicode character, a JSON Schema that's missing the case the model should have produced — all silently degrade output. Treat the schema as production code: version it, test it, monitor "schema-failure-was-actually-correct" cases.

15.7 Reference — Schema-Constrained Sampler

"""~80-line constrained JSON-int sampler. Real Outlines is much more general."""
import torch, re

def schema_to_fsm(schema: dict):
    """For schema {'type': 'object', 'properties': {'age': {'type': 'integer'}}}.
    Build a tiny FSM with states START → AFTER_BRACE → KEY → COLON → DIGITS → END."""
    states = ["start", "key", "colon", "digits", "end"]
    transitions = {
        "start":  {'{': "key"},
        "key":    {'"age": ': "colon"},
        "colon":  {d: "digits" for d in "0123456789"},
        "digits": {**{d: "digits" for d in "0123456789"}, '}': "end"},
    }
    return states, transitions, "start"

def constrained_decode(model, tokenizer, schema, max_tokens=32):
    states, trans, state = schema_to_fsm(schema)
    out = ""
    for _ in range(max_tokens):
        logits = model(tokenizer.encode(out, return_tensors="pt"))[0, -1]
        allowed = list(trans.get(state, {}).keys())
        mask = torch.full_like(logits, float("-inf"))
        for tok_str in allowed:
            tok_id = tokenizer.encode(tok_str, add_special_tokens=False)[0]
            mask[tok_id] = logits[tok_id]
        next_id = torch.argmax(mask).item()
        next_str = tokenizer.decode([next_id])
        out += next_str
        state = trans[state][next_str]
        if state == "end": break
    return out
Gates are how LLMs become reliable

Production agents at scale are essentially LLMs orchestrated by deterministic code. The gate is the contract that lets you compose. Anyone shipping LLMs in 2026 without constrained decoding is one prompt away from production incidents.

Better models won't need them

Constrained decoding is a 2023-era workaround. Frontier models in 2026 already produce valid JSON 99.9% of the time when asked. The remaining failures are usually cases where the schema was wrong, not the model. Gates add maintenance burden for diminishing returns.

❓ Open questions

  • How much quality is lost when constrained decoding rules out near-valid outputs the model would have self-corrected?
  • Can we lift constrained decoding from grammars to "valid against this database schema and these business rules"?
  • What's the right benchmark for the LLM + checker (AlphaProof-style) loop on tasks beyond math?
