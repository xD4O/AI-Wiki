CHAPTER 14Part IV · Systems & Control

Agentic Orchestration

The systems-engineering chapter. How do you actually run an LLM-powered workflow that retries correctly, survives partial failure, is observable, and doesn't cost $10K/day by accident? State machines, durable execution, compound AI.

2023-06 ReAct pattern 2024-01 LangGraph v0.1 2024-02 Compound AI Systems (BAIR) 2024-Q3 Restate, DBOS launch 2024-Q4 Temporal AI workflows 2025-2026 LangGraph production default
🧒 ELI5 — explain like I'm five

A simple agent is like a single person doing a chore with no supervisor: "think, do something, check, try again." That works for short chores.

For a two-hour chore with many steps — book a flight, send emails, update a spreadsheet, run a migration — you want more structure. State machines say "at each step you can only move to a few allowed next steps." Durable execution says "if something crashes halfway, we remember exactly where we were and resume." Compound AI systems say "the whole thing is really many tiny LLM calls, a retriever, a verifier, a router — and we should design it like that explicitly."

These ideas together are what make 2026 agents actually ship in production.

14.1 Why the Single ReAct Loop Breaks

Volume II Ch 08 introduced ReAct as the default agent pattern. For a 60-second task with a handful of tools, it works. For a 2-hour, 200-step workflow that spans APIs, databases, humans, and half a dozen LLM calls, it falls apart:

  • No checkpoints. A failure at step 120 means replaying from step 0, and most tool calls have side effects.
  • No types. Every step's output feeds the next step's prompt; schema drift breaks everything downstream silently.
  • No human-in-the-loop. Some decisions need approval; ReAct has no clean "pause for approval" primitive.
  • No observability. You can't debug a 200-step run from raw LLM logs.

14.2 LangGraph — State Machines Over LLMs

LangChain's LangGraph (2024) flipped the model: an agent is a graph. Nodes are pure functions (often LLM calls) with typed inputs/outputs. Edges are conditional — "after the planner node, if the output is a tool call, go to the tool node; if it's an answer, go to END."

The whole graph has persisted state. Every node execution is a checkpoint. Failures resume from the last checkpoint. Human-in-the-loop is a first-class primitive: you can literally interrupt the graph at any node, wait for approval, and resume.

LangGraph: explicit nodes, typed edges, checkpointed state. The orchestrator pattern that won production in early 2026. 
from langgraph.graph import StateGraph, END
from typing import TypedDict

class State(TypedDict):
    messages: list
    plan: str | None
    tool_result: str | None
    approved: bool

def planner(s: State) -> State:
    s["plan"] = llm.invoke(f"Plan: {s['messages']}")
    return s

def router(s: State) -> str:
    if "tool:" in s["plan"]:      return "tool"
    if "needs_approval" in s["plan"]: return "human"
    return "final"

g = StateGraph(State)
g.add_node("plan", planner).add_node("tool", run_tool).add_node("human", ask_human).add_node("final", finalize)
g.add_edge("__start__", "plan")
g.add_conditional_edges("plan", router, {"tool": "tool", "human": "human", "final": "final"})
g.add_edge("tool", "plan"); g.add_edge("human", "plan"); g.add_edge("final", END)
app = g.compile(checkpointer=SqliteSaver())

14.3 Durable Execution — Temporal, Restate, DBOS

LangGraph gives you checkpoints for LLM workflows. Durable execution frameworks give you a stronger guarantee for any long-running workflow, LLM or not:

  • Every step's inputs and outputs are journalled.
  • If the process crashes mid-step, on restart the framework replays the journal until the crash point and resumes.
  • Non-deterministic operations (LLM calls, network requests) are only ever executed once; their recorded outputs are replayed on resumption.

This is the abstraction that makes "the agent ran for two hours, something crashed, just keep going" actually safe.

  • Temporal.io — the mature option, cross-language, used at Uber/Stripe/Netflix scale.
  • Restate — lighter-weight, Rust-based, focused on stateful services and AI agents.
  • DBOS — Mike Stonebraker's take: durable execution as a database extension. Every step becomes a DB transaction.
  • Inngest, Dagger, Hatchet — commercial alternatives, AI-agent-flavoured.
# Temporal-style workflow around an LLM agent
@workflow.defn
class ResearchAgent:
    @workflow.run
    async def run(self, topic: str) -> str:
        query = await workflow.execute_activity(plan_queries, topic, retry_policy=...)
        # activities are non-deterministic; the LLM call is recorded
        docs  = await workflow.execute_activity(search, query, retry_policy=...)
        draft = await workflow.execute_activity(write_draft, docs, retry_policy=...)
        # wait for human approval — durable timer, no resource held
        approved = await workflow.wait_condition(lambda: self.approved, timeout=86400)
        return await workflow.execute_activity(finalize, draft)

14.4 Compound AI Systems (BAIR)

Zaharia, Khattab et al. (Berkeley 2024) published a short manifesto making a clean argument: most frontier capability in 2024–2026 comes from compound AI systems — retrievers + rankers + models + verifiers wired together — not from monolithic "one big model" deployments.

Implication: performance improvements come from system-level redesign more than from model swaps. Practical consequence: engineering teams now own a topology, not a prompt.

14.5 Typed Workflows & Agent SDKs

  • Pydantic-AI — Python-first, typed agent framework; validates all I/O against Pydantic models.
  • OpenAI Agents SDK — minimal, handoff-based, official OpenAI.
  • Anthropic's skills (Vol II Ch 06) — a lighter "capability as markdown + optional scripts" convention.
  • Microsoft AutoGen — conversational-agent-first; has pivoted toward typed workflows in 2025.

14.6 Observability, Replay, Determinism

A production agent's spans look nothing like a request trace. A single "chat" might fan out to tens of LLM calls, hundreds of tool calls, dozens of cache hits. Observability requirements:

  • Correlation ID per top-level request; all sub-spans carry it.
  • Input + output tokens per span, for cost and latency attribution.
  • Replay — given the journal, re-run the workflow deterministically, substituting recorded LLM outputs.
  • Diff two runs (same input, two prompt versions) at the span level — this is the eval surface.

Tools: Langfuse, Helicone, LangSmith, W&B Weave, Arize Phoenix, OpenTelemetry. See Vol II Ch 11 for practitioner-level coverage.

14.7 Reference — Mini State-Machine

"""~80-line LangGraph-lite: typed state, nodes, edges, checkpoints."""
import json, sqlite3
from typing import Callable, Any

class Graph:
    def __init__(self, state_schema: type):
        self.nodes: dict[str, Callable] = {}
        self.edges: dict[str, Callable] = {}   # node -> (state) -> next_node
        self.schema = state_schema

    def node(self, name: str, fn: Callable):  self.nodes[name] = fn;  return self
    def edge(self, name: str, router: Callable):  self.edges[name] = router;  return self

    def run(self, start: str, initial: dict, checkpoint: sqlite3.Connection, run_id: str) -> dict:
        s, cur = dict(initial), start
        while cur != "END":
            s = self.nodes[cur](s)                       # run node
            checkpoint.execute("INSERT INTO runs VALUES (?, ?, ?)",
                               (run_id, cur, json.dumps(s)))
            checkpoint.commit()
            cur = self.edges[cur](s)                     # route
        return s

    def resume(self, checkpoint, run_id, start_if_missing, initial):
        row = checkpoint.execute("SELECT node, state FROM runs WHERE id=? "
                                 "ORDER BY rowid DESC LIMIT 1", (run_id,)).fetchone()
        if not row: return self.run(start_if_missing, initial, checkpoint, run_id)
        node, s = row[0], json.loads(row[1])
        return self.run(self.edges[node](s), s, checkpoint, run_id)
Typed state machines are the answer

Single-loop ReAct doesn't survive production. LangGraph + Temporal gives you retry, checkpoint, human-in-the-loop, and observability for free. Compound AI systems outperform single-model stacks. This is the enterprise default.

The abstraction tax is real

State machines force you to name every edge up front; agents are most useful exactly when the next step is unknown. Compound systems add latency and debugging complexity. For many tasks, a smarter model + a plain ReAct loop is easier to reason about than 20 LangGraph nodes.

❓ Open questions

  • Does a typed state machine + weaker model beat ReAct + stronger model at the same cost? (Often yes, but noisy.)
  • Is there a "standard library" of composable nodes emerging (retrieve, verify, route, finalise)?
  • How do we test a workflow that spans hours without running hours of real time?
