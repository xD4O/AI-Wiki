CHAPTER 11Part III · Reasoning & Training

Memory, Titans & Continual Learning

Vol II treated context as the model's only memory. The 2024-2025 wave — Titans, test-time training, external memory — tries to make models accumulate beyond the window.

2023 MemGPT / Letta 2024-07 TTT for sequences (Sun et al.) 2024-12 Titans (Google Research) 2025 mem0 production 2025-11 "Continual learning, not training" (arXiv)
🧒 ELI5 — explain like I'm five

A language model is like a student who can read the current page of a book but instantly forgets the last page. We've been cheating by keeping more of the book open (longer context) or by giving the student a little notebook to summarise (RAG).

Titans gives the student three kinds of memory: a short notebook for this sentence, a big notebook for this chapter, and a permanent journal that updates slowly as the student reads. It's messy, but it's the first serious attempt at a student who gets better as they read, not only after they've been re-trained.

11.1 Titans — Three Kinds of Memory

Titans (Behrouz, Zhong, Mirrokni — Google Research 2024) proposes a block with three memory modules:

  • Short-term attention — the familiar transformer attention over a recent window.
  • Long-term neural memory — a small MLP whose weights are updated at inference time based on "surprise" (reconstruction error).
  • Persistent memory — learned task-level key-value pairs, fixed at training time.

The elegant part: the long-term memory is itself a neural net that learns online. The model literally updates its own weights as it reads, at inference — a kind of neural note-taking.

Titans divides memory by time scale — milliseconds (attention), minutes (online MLP), months (persistent). Each has different update rules.

11.2 Test-Time Training

Titans' long-term memory is a special case of Test-Time Training (TTT): let the model update itself during inference on an auxiliary self-supervised task. Sun et al. (2024) showed this works well for long-sequence modelling — better than SSMs at similar cost.

TTT's claim is philosophically interesting: the line between "training" and "inference" is not fundamental. A model that keeps training during deployment is still a model, just one with an unfrozen optimiser.

11.3 External Memory — MemGPT, Letta, mem0

A different tradition: keep the model frozen, add an explicit key-value memory store, and train the model to issue memory reads and writes. Vol II Ch 04 treated this as practitioner-level infrastructure. At the research level:

  • MemGPT / Letta — virtual context manager; hierarchical main/archival memory with swap.
  • mem0 — production-grade semantic memory layer.
  • MemoryBank, LongMem — academic precursors.

11.4 In-Weight Continual Learning

The harder problem: a model that genuinely updates its weights from deployment, without catastrophically forgetting earlier knowledge. Current approaches:

  • LoRA stacking — append a new LoRA for each task; costs memory but keeps forgetting local.
  • EWC / SI — classical elastic-weight-consolidation methods still live on in the continual-learning subfield.
  • Replay — store a subset of old data and re-finetune periodically.

A late-2025 position paper, "Continual Learning, Not Training", argues this is the next frontier — not bigger pretrains, but models that learn from deployment experience with provable non-forgetting.

Real memory is the next frontier

Scaling context length to 1M tokens is a brittle solution. Real intelligence accumulates. Titans and TTT are early evidence that in-weight update at inference can work. The next decade is about unfrozen models.

Context is enough

Every memory architecture so far has been weaker than just-longer-context on benchmarks. RAG + 1M-context + prompt caching already solves 95% of "memory" use cases. In-weight continual learning remains an elegant idea without a shipping win.

❓ Open questions

  • Can Titans-style online updates be made reversible / auditable for safety?
  • What's the right evaluation for "a model that genuinely learns from use"? (There's no good one.)
  • Is there a privacy story for in-weight personalised memory that respects data boundaries?
