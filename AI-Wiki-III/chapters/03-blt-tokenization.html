CHAPTER 03Part I · Architecture

Byte Latent Transformer & the End of Tokenization

Meta FAIR's BLT is the most credible 2024-2026 attempt to kill the BPE tokenizer. Dynamic byte patches, a local encoder/decoder, and a latent transformer that matches Llama 3 on equal compute.

2015 BPE adopted by NMT 2023-05 MegaByte (Meta) 2024-04 SpaceByte 2024-12 BLT (Meta FAIR) 2025 BLT follow-ups at 8B+ scale
🧒 ELI5 — explain like I'm five

Normally, before a language model reads text, we chop it into pieces called tokens. A token is usually 3-4 letters, sometimes a whole word. This chopper was decided before the model was trained and it never changes. That's weird: it's like handing a reader a book where some words have been pre-glued together at random.

The Byte Latent Transformer (BLT) gets rid of the chopper. It reads raw bytes — the actual letters and emoji and symbols — and uses a tiny helper network to decide where natural chunks start and stop. If the text is predictable ("the next word is probably 'cat'"), the chunks are long. If the text is surprising (a name, a code snippet, rare language), the chunks get shorter so the main model can pay more attention.

Result: the model does see individual letters, so it can count the Rs in "strawberry." And chunks are chosen per-sentence, not per-vocabulary, so minority languages and code don't pay the BPE tax.

3.1 Why Kill Tokenization?

We covered the failure modes in Ch 01. Restated: BPE is a compression, not a representation. It was chosen to make sequence lengths manageable in 2015. Every problem downstream (character-level reasoning, non-English tax, spelling drift) is a symptom of that compression leaking into semantics.

BLT's thesis: letting the model allocate compute per-byte, with patch boundaries chosen by entropy rather than frequency, fixes all five symptoms without losing efficiency.

3.2 The BLT Architecture

BLT's three pieces. Two small local networks at the edges, one large latent transformer in the middle. All three trained end-to-end.

3.3 Entropy-Based Dynamic Patches

The how that makes BLT work: patches aren't fixed-width and aren't chosen by a pre-trained tokenizer. A small auxiliary model predicts the entropy of the next byte; wherever entropy crosses a threshold, that's a patch boundary.

Effect: in predictable regions ("..the cat sat on") patches are long, saving latent-transformer compute. In surprising regions (rare names, URLs, code) patches are short, spending more compute where the hard decisions are.

This is a quiet revolution: inference-time compute is now per-input, not per-token, for free.

3.4 Results & What BLT Proves

AxisBLT vs. Llama 3 (equal FLOPs)
Perplexity (English)Matches at 8B scale.
Character-level tasksClearly better — counting letters, reversal, arithmetic structure.
Non-EnglishBetter throughput (no token-inflation tax); comparable or better quality.
Noisy inputs (typos, Unicode)More robust — the model sees the bytes, not a mangled BPE fallback.
ThroughputCompetitive; patches keep sequence length manageable.

The paper's central claim isn't "BLT is strictly better." It's "at equal compute, ditching BPE doesn't cost you anything and buys you character-level competence and multilingual fairness." If that holds through 70B, BPE becomes optional.

3.5 Prior Art

  • MegaByte (Meta, 2023) — fixed-width byte patches, a global latent transformer and local byte transformer. BLT's direct ancestor; the novelty of BLT is the dynamic entropy-based patching.
  • SpaceByte (2024) — patch boundaries at whitespace; simpler heuristic, still competitive.
  • Charformer / CANINE — older approaches that tried to learn tokenization end-to-end.
  • tokenizer-free research more broadly — ByT5 (2022), Perceiver IO, HourGlass, etc.

3.6 Reference — A Boundary Detector

import torch, torch.nn as nn

class EntropyBoundary(nn.Module):
    """Predict per-byte entropy; cut when it exceeds a threshold."""
    def __init__(self, d=128, vocab=256, threshold=2.5):
        super().__init__()
        self.embed = nn.Embedding(vocab, d)
        self.lstm  = nn.LSTM(d, d, batch_first=True)
        self.head  = nn.Linear(d, vocab)
        self.thresh = threshold

    def entropy(self, bytes_):                    # bytes_: (L,) int64
        x, _ = self.lstm(self.embed(bytes_).unsqueeze(0))
        p = self.head(x).softmax(-1)              # (1, L, 256)
        return -(p * (p + 1e-9).log()).sum(-1).squeeze(0)   # (L,)

    def patches(self, bytes_):
        H = self.entropy(bytes_)
        cuts = (H > self.thresh).nonzero().flatten().tolist()
        # return list of (start, end) byte ranges
        spans, prev = [], 0
        for c in cuts + [len(bytes_)]:
            if c > prev: spans.append((prev, c))
            prev = c
        return spans

The real BLT paper uses a jointly-trained entropy model; this is the same idea with an LSTM stand-in.

Case for BLT

Tokenization is a structural wart. BLT solves character-level tasks, multilingual fairness, and robustness to noise without sacrificing perplexity. Every new model after 8B should be byte-level.

— Meta FAIR (Pagnoni et al.), Karpathy (sympathetic)

Case against

BLT is slower per wall-clock step; the entropy model adds complexity; most of the world's production deployments already work around BPE with special tokens. The juice is not worth the squeeze unless BLT ships at 70B+ with matching quality.

— most production frontier labs (April 2026)

❓ Open questions

  • Does BLT scale past 8B with the same quality gains, or does the entropy boundary model become the bottleneck?
  • Can we combine BLT patches with Mamba-style SSMs (cheap per-byte + cheap per-patch)?
  • Is there an analogous "kill tokenization" move for multimodal tokenizers (VQ codebooks, image patches)?
