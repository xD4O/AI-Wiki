CHAPTER 02 Part I · Using Models

Local Models: Ollama & LM Studio

Run capable open-weight models on your own hardware. We'll cover VRAM math, quantization, Ollama, LM Studio, and when to graduate to vLLM.

2.1 Why Local

There are four reasons to run a model on your own hardware:

  • Privacy. Medical notes, legal documents, source code — data that cannot leave the machine.
  • Cost. A local 70B model running 24/7 costs electricity. A comparable API spend is four figures a month.
  • Latency. No round-trip to a data centre. First-token latency under 100 ms is achievable.
  • No rate limits, no outages. When your workflow depends on 10,000 calls at 3 a.m., you own the throughput.

Open-weight models have closed most of the quality gap on non-frontier tasks. By April 2026, a well-quantized 32B–70B model is routinely within a few points of the best closed models on coding, summarization, and structured extraction.

2.2 Hardware Reality Check — VRAM Math

The first question every would-be local-LLM user asks: "will it fit?" The formula is:

$$\text{VRAM (GB)} \approx \text{params (B)} \times \dfrac{\text{bits}}{8} + \text{overhead}$$

"Overhead" is 1–3 GB for KV cache at small contexts, more as context grows. A rough table:

ModelParamsFP16 (no quant)Q8Q4_K_MQ3_K_S
Llama 3 8B8B16 GB8 GB4.8 GB3.6 GB
Qwen 2.5 32B32B64 GB32 GB19 GB14 GB
Llama 3.3 70B70B140 GB70 GB42 GB31 GB
DeepSeek-V3 671B (MoE, ~37B active)671B total1.3 TB671 GB~400 GB~300 GB
What fits where. Quantization is almost free quality-wise down to Q4; below that, you start to feel it.

2.4 Ollama Deep Dive

Ollama is the easiest way to get a local LLM running. It bundles llama.cpp under an OpenAI-compatible HTTP server with a CLI frontend.

# install (macOS / Linux)
curl -fsSL https://ollama.com/install.sh | sh

# pull a model (automatically picks Q4_K_M if you don't specify)
ollama pull llama3.3:70b
ollama pull qwen2.5:32b
ollama pull deepseek-r1:32b

# run a one-shot
ollama run llama3.3:70b "What's the capital of France?"

# list what's installed
ollama list

# watch VRAM
ollama ps

Modelfile — the little-known power feature

A Modelfile lets you bake a system prompt, sampling parameters, and a template into a named model so every caller gets the same behavior.

# ./Modelfile
FROM llama3.3:70b

PARAMETER temperature 0.2
PARAMETER num_ctx 16384

SYSTEM """
You are a senior Python code reviewer. Respond in bullet points.
Flag security issues with 🚨 and style issues with 🎨.
"""
ollama create pyreviewer -f ./Modelfile
ollama run pyreviewer "review this: import pickle; pickle.loads(user_input)"

HTTP API (OpenAI-compatible)

from openai import OpenAI

client = OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")

r = client.chat.completions.create(
    model="qwen2.5:32b",
    messages=[{"role": "user", "content": "factorial of 10"}],
)
print(r.choices[0].message.content)

# Tool calling works too — same schema as OpenAI
r = client.chat.completions.create(
    model="llama3.3:70b",
    messages=[{"role": "user", "content": "what is 23 * 47?"}],
    tools=[{
        "type": "function",
        "function": {
            "name": "multiply",
            "parameters": {"type": "object",
                           "properties": {"a": {"type": "number"}, "b": {"type": "number"}}},
        }
    }],
)

Embeddings from the same daemon

r = client.embeddings.create(model="nomic-embed-text", input="hello world")
print(len(r.data[0].embedding))  # 768

2.5 LM Studio Deep Dive

LM Studio is a desktop GUI that wraps llama.cpp (and MLX on Mac). Aimed at people who want a "ChatGPT-but-local" experience first, and an API server second. Strengths:

  • Model discovery. Search HF from inside the app; it filters by what fits your hardware.
  • Playground UI. Fiddle with system prompts, temperature, and top-p live.
  • OpenAI-compatible server. Flip the toggle and you have localhost:1234/v1.
  • MLX first-class on Apple Silicon. Substantially faster than GGUF on M-series for the same model.
Ollama or LM Studio?

Pick Ollama if you live in the terminal and want CLI + API. Pick LM Studio if you prefer a GUI, are on a Mac (MLX), or want to browse/try models before committing.

2.7 Routing Between Local and Frontier

A common pattern in production: use a local model for the 95% of requests that are easy, and escalate to a frontier API for the hard ones. Because Ollama and LM Studio speak OpenAI-compatible JSON, routing is a one-line swap of base_url.

def route(task_difficulty: str):
    if task_difficulty == "easy":
        return OpenAI(base_url="http://localhost:11434/v1", api_key="ollama"), "qwen2.5:32b"
    return Anthropic(), "claude-opus-4-7"

The "difficulty" signal can come from a small classifier, a rule (e.g., "any query involving private data stays local"), or from the local model itself — it returns a confidence score and we escalate on low confidence.

Sidebar: DGX Spark notes

For owners of the Nvidia DGX Spark (Grace-Blackwell desktop, 128 GB unified): sweet spot is Llama 3.3 70B at Q6, Qwen 2.5 32B at FP16, or DeepSeek-V3 at Q3. Ollama runs out of the box; vLLM needs the CUDA 12.5+ wheel. Thermally the Spark is quiet at steady state but throttles during long generations — set a fan curve.

Sidebar: Apple Silicon path

On an M3/M4 Max or Ultra: prefer LM Studio with MLX over Ollama. MLX is 30–60% faster than GGUF at the same quant level thanks to Metal + unified memory. For 70B at Q4 you want 64 GB RAM minimum; 128 GB is comfortable.
