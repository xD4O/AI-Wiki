CHAPTER 01 Part I · Using Models

From Chatbot to Agent

What do we actually mean by "agent"? We'll draw a spectrum from single-turn chat to autonomous worker, define the agent loop in one paragraph, and survey the apps already shipping on it.

1.1 The Agency Spectrum

Call something an "agent" long enough and the word loses meaning. Useful definitions exist on a spectrum, not a binary. On one end: a chatbot that returns text and nothing else. On the other: a process that plans, executes, revises, and reports back hours later without supervision. Everything in between is a dial.

The dial has two knobs:

  • Authority — how many irreversible actions the system can take before checking with a human.
  • Horizon — how long it runs between human inputs.

A "yes/no" QA bot has zero authority and a horizon of one turn. A fully autonomous coding agent that opens PRs and merges them has high authority and a horizon of hours. The interesting design work is picking the right point on the dial for your task — not maximizing either axis.

The agency spectrum. Most products in 2026 live between "tool-using LLM" and "agent loop."

1.2 Levels of Agency

Anthropic's engineering team (and others) use a rough five-level taxonomy. Treat it as SAE-levels-for-self-driving, not physics.

LevelNameWho decides?Example
L0Pure chatHuman does everythingChatGPT conversation
L1Tool-assistedHuman picks tool, model fills inCode interpreter, Wolfram plugin
L2Tool-usingModel picks tool; human reviews each stepChatGPT with function calling
L3Agent loopModel plans & executes many steps; human reviews at checkpointsClaude Code, Cursor Agent
L4Supervised autonomyModel runs end-to-end; human reviews only the resultDevin, Replit Agent
L5Open-ended autonomyModel operates indefinitely with goals, not tasksNot yet shipping reliably
L4+ is not where most of the value is

In 2026, most production value is captured at L3: a tight human-in-the-loop agent that saves the human 10× on well-scoped tasks. L5 systems that "just go off and do stuff" still burn money on tangents. Agency is a tool, not a goal.

1.3 The Agent Loop in One Paragraph

An agent is a loop. At each step the model sees the history (goal, past actions, past observations), emits either a tool call or a final answer, and the runtime executes the tool and appends the result to the history. The loop terminates when the model says it's done, when a budget is exhausted, or when a human interrupts. That's it. Everything else — planning, reflection, multi-agent orchestration — is a pattern on top of that loop.

The canonical agent loop. ReAct, plan-execute, Reflexion — all variations on this skeleton.

1.4 Case Studies

Claude Code

A terminal-native coding agent. Tools are file I/O, bash, web fetch, plus MCP servers the user configures. Typical run: 20–200 tool calls over 2–10 minutes. Human approves write-type actions by default. Ships as a CLI, VS Code / JetBrains extensions, and a web/iOS app as of 2026.

Cursor & Cursor Agent

An editor-first experience. The inline "tab" completion is L1; the Composer / Agent modes are L3. Strong model routing (cheap model for completions, frontier model for the agent loop).

Devin

Cognition's agent. Aimed at L4 — give it a Linear ticket, come back to a PR. Uses a sandboxed VM so it can run servers, browsers, and arbitrary code. Works best on narrow, well-specified tasks.

Replit Agent

Full-stack app generator inside Replit's cloud IDE. The value prop is less "better code" and more "zero-to-deployed in five minutes" — the agent controls the build, deploy, and DB provisioning too.

Custom agents

Most production agents are domain-specific: a support-ticket triager that can read CRM data and escalate, a data-analyst agent that lives in a Jupyter kernel, a code-review bot that watches one repo. These win because their tool surface is small and their evals are concrete.

1.6 A 20-Line ReAct Agent

Here is the entire agent loop — nothing fancy, no framework, just the Anthropic SDK. Read this and you understand 80% of what every "agent framework" is doing.

from anthropic import Anthropic

client = Anthropic()
TOOLS = [{
    "name": "bash",
    "description": "Run a shell command and return stdout/stderr.",
    "input_schema": {"type": "object", "properties": {"cmd": {"type": "string"}}, "required": ["cmd"]},
}]

def run_tool(name, inp):
    import subprocess
    return subprocess.run(inp["cmd"], shell=True, capture_output=True, text=True).stdout

def agent(goal, max_turns=12):
    messages = [{"role": "user", "content": goal}]
    for _ in range(max_turns):
        r = client.messages.create(model="claude-opus-4-7", max_tokens=1024, tools=TOOLS, messages=messages)
        messages.append({"role": "assistant", "content": r.content})
        if r.stop_reason == "end_turn":
            return next(b.text for b in r.content if b.type == "text")
        tool_uses = [b for b in r.content if b.type == "tool_use"]
        messages.append({"role": "user", "content": [
            {"type": "tool_result", "tool_use_id": t.id, "content": run_tool(t.name, t.input)}
            for t in tool_uses
        ]})
    return "budget exhausted"

print(agent("How many Python files are in this directory? Use bash to find out."))
Same thing with a local model

Swap Anthropic() for an OpenAI-compatible client pointed at Ollama's localhost:11434/v1 — with a tool-calling model like qwen2.5:32b, llama3.3:70b, or deepseek-r1:32b, the same loop runs locally. See Chapter 02.
