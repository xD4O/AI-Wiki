CHAPTER 04 Part II · Context & Memory

Context Engineering

Treat the context window as a resource to be engineered, not dumped into. Token economy, caching, lost-in-the-middle, and compaction.

4.1 Context ≠ Memory

Transformers don't have "memory" in the human sense. Every forward pass re-reads the entire context window from scratch. What the model "remembers" at turn 30 is simply whatever is still in the context at turn 30. Drop something from the context and it's gone.

This has two implications:

  • Whatever you want the model to know at decision time, it must be in the window at decision time.
  • The context window is the only working memory. External stores (vector DBs, scratchpads) become useful only when you retrieve from them into the window.

4.2 The Token Economy

Context has three costs:

  • Dollars. Input tokens are cheaper than output, but a 100K-token prompt × 10K agent steps is no longer cheap.
  • Latency. Prefill scales roughly linearly with prompt length on most accelerators. A 200K prompt adds real wall-clock time.
  • Quality. Even when the context fits, attention gets diluted at large lengths. More is not always better.
A typical agent-run context. Cache the left side, evolve the right side.

4.3 Placement Matters — Lost in the Middle

Liu et al. (2023) showed that LLMs attend more to the beginning and end of long contexts than the middle. Frontier 2026 models are better at this than 2023 models, but the effect still shows up at 128K+.

The U-shape: put critical info at the start or end; never only in the middle.

4.4 Compaction & Rolling Summaries

When a conversation outgrows the window, you have three options:

  1. Truncate. Drop the oldest turns. Fastest, loses information.
  2. Summarize. Replace the oldest N turns with a model-generated recap. Preserves gist, loses verbatim.
  3. Retrieve. Store everything externally; at each turn, pull only the relevant slices back in (Ch 05).
# Rolling-summary conversation manager (minimal)
class RollingConvo:
    def __init__(self, client, model, budget_tokens=30_000):
        self.client, self.model, self.budget = client, model, budget_tokens
        self.summary = ""          # living recap of old turns
        self.recent = []           # last N turns verbatim

    def turn(self, user_msg):
        self.recent.append({"role": "user", "content": user_msg})
        messages = ([{"role": "system", "content": f"Conversation so far:\n{self.summary}"}]
                    if self.summary else []) + self.recent
        r = self.client.chat(model=self.model, messages=messages)
        self.recent.append({"role": "assistant", "content": r})
        if self._tokens(messages) > self.budget:
            self._compact()
        return r

    def _compact(self):
        # summarise everything except the last 4 turns
        old = self.recent[:-4]
        self.summary = self.client.chat(model=self.model, messages=[
            {"role": "system", "content": "Summarise the conversation. Keep decisions, facts, and open questions."},
            *old,
        ])
        self.recent = self.recent[-4:]

4.5 Prompt Caching

Anthropic and OpenAI both support prompt caching: a stable prefix (system prompt, tool specs, static docs) is hashed; subsequent calls with the same prefix read it from cache at ~10% of the token price and with far lower latency.

Structure prompts for cache hits

Order your context: most-stable → least-stable. Static system prompt first, then static docs, then memory, then the fresh user message last. Anything that changes invalidates everything after it.

4.6 System Prompt as Contract

The system prompt is where you encode behavior that must hold for every turn: role, format, safety rails, tool usage policy. It is not where you put the user's current task.

4.7 Context Pollution & the First-Class Citizen Principle

Anthropic engineers have written about the "first-class citizen" principle for agents: at each step, the model should see only what's relevant to that step. Everything else is pollution — it dilutes attention and costs tokens.

  • Drop old tool outputs that are no longer referenced.
  • Summarize subtask transcripts when returning to the main loop.
  • Don't carry the entire README into every coding edit — retrieve just the relevant file.

4.8 Code — Cache-Aware Layout

def build_prompt(user_query, retrieved_docs):
    # 1. stable system (cached)
    system = [{
        "type": "text",
        "text": STATIC_SYSTEM_PROMPT + TOOL_DEFINITIONS,
        "cache_control": {"type": "ephemeral"},
    }]
    # 2. semi-stable retrieved docs (cached if same doc set repeats)
    system.append({
        "type": "text",
        "text": format_docs(retrieved_docs),
        "cache_control": {"type": "ephemeral"},
    })
    # 3. fully dynamic user turn (never cached)
    return dict(system=system, messages=[{"role": "user", "content": user_query}])
