CHAPTER 06 Part II · Context & Memory

Skills & Reusable Prompts

Turning a working prompt into a named, versioned capability that a model can load on demand. The SKILL.md convention, composition, and why it beats sub-agents for many tasks.

6.1 From Ad-hoc Prompts to Skills

You write a prompt that works. You reuse it. You paste it into a Notion doc. Six months later, two teams are using slightly-different copies and nobody remembers who owns it.

A skill is the cure: a named, versioned, self-describing capability. The model loads it only when the triggering condition matches, so it doesn't pollute the context until it's needed. Anthropic's Agent Skills, Claude Code skills, and the Hugging Face smolagents "tool" pattern all converge on the same idea.

6.2 The SKILL.md Format

A skill is a directory. At minimum, a SKILL.md with YAML frontmatter — optionally scripts, examples, sub-skills, references.

my-skill/
├── SKILL.md          # trigger + instructions
├── scripts/
│   └── run_tests.py  # optional helper the model can invoke
├── examples/
│   └── sample.json
└── references/
    └── api-spec.md
---
name: code-reviewer
description: |
  Review a diff for security issues, style problems, and missing tests.
  Use when the user asks to "review", "audit", or "check" code changes.
version: 1.3.0
tools: [bash, read_file]
---

# Code Reviewer

You are a senior engineer doing a careful code review.

## Steps
1. Read the diff with `bash: git diff HEAD~1`.
2. Flag 🚨 security issues, 🎨 style issues, and ❓ unclear intent.
3. For each finding, cite the file:line and suggest a fix.
4. If tests are missing for new code paths, say so explicitly.

## Output format
Reply in markdown, sections in this order: Summary, Security, Style, Tests, Suggestions.
description matches the user's task — no context pollution. The skill lifecycle. The description in the frontmatter is what gates loading.

6.3 Composition — Skills That Call Skills

A skill body can reference other skills by name. When the model decides to follow a reference, the target skill is loaded into context. This turns your skill library into a directed graph of capabilities.

# Code Reviewer

Before writing comments, invoke `run-tests` to confirm the diff builds.
If tests fail, invoke `fix-failing-tests` instead of reviewing.

6.4 Skill vs. Tool vs. Sub-Agent

ChoiceUse when…Lifecycle
ToolA deterministic function: read_file, run_bash, http_getAlways available; the model calls it by name
SkillA repeatable procedure — a "how-to" recipe the model should followLoaded on demand when description matches
Sub-agentA task needs its own context window, different tools, or isolationSpawned for one task; receives a fresh context
Picking one

If the procedure is the same every time: tool. If the procedure is stable but needs prose-level judgment: skill. If the procedure wants its own context that doesn't pollute the main loop: sub-agent.

6.5 Authoring a Skill From Scratch

Anthropic ships a skill-creator skill that helps you bootstrap new skills. The rough process:

  1. Write the working prompt in a chat first. Iterate until it works.
  2. Factor out the stable procedure. Replace instance-specific inputs with {placeholders}.
  3. Write the description — this is the trigger. Be specific about when to use it AND when not to.
  4. Add scripts only when a deterministic step is worth automating (e.g., running a linter).
  5. Test with an eval set of 5–10 real inputs.
# Programmatic invocation via the SDK
from anthropic import Anthropic
client = Anthropic()

r = client.messages.create(
    model="claude-opus-4-7",
    max_tokens=4000,
    system=open("skills/code-reviewer/SKILL.md").read(),
    messages=[{"role": "user", "content": f"Review this diff:\n\n{diff_text}"}],
)
print(r.content[0].text)

6.6 Org-Level Skill Libraries

The payoff of the skill convention is not at the individual level but at the team level. A well-curated skill library is your institutional prompt memory:

  • runbooks/incident-response — mirrors your SRE playbook exactly.
  • analytics/cohort-query — how your data team writes SQL against the warehouse.
  • hiring/phone-screen-summary — the template every recruiter uses.

Store them in git. Review changes in PRs. Keep per-skill eval sets. This is where "prompt engineering" becomes "prompt ops."
