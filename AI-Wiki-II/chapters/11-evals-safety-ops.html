11.1 Evals Are 80% of the Work

A working demo needs one good example. A production agent needs to be right 95% of the time on inputs it has never seen. The bridge between those two worlds is evaluation. Every serious team building with LLMs in 2026 spends most of their time on evals — not on prompts.

The eval pyramid: many cheap checks at the base, a handful of end-to-end task evals at the tip.

11.2 Task Evals

  • Exact-match / F1 — for tasks with a ground-truth string.
  • Code correctness — run the produced code against unit tests.
  • LLM-as-judge — a frontier model grades an assistant's output on a rubric. Great for open-ended tasks; bias the judge model and itemise the rubric.
  • Pairwise preference — "is A better than B?" is easier for a judge than grading absolutely.
RUBRIC = """Score 1-5 on: correctness, completeness, tone.
Return JSON: {correctness: int, completeness: int, tone: int, reason: str}"""

def judge(question, answer, gold):
    msg = f"Q: {question}\nGOLD: {gold}\nANSWER: {answer}"
    return parse_json(client.chat(system=RUBRIC, user=msg))

11.4 Red-Teaming & Prompt-Injection Tests

Ship a prompt-injection regression suite alongside your normal tests. At minimum:

  • Obvious injections in user input ("ignore all previous instructions…")
  • Injections in retrieved content (a malicious line in a RAG doc)
  • Injections in tool outputs (a compromised webpage fetched by the agent)
  • Data-exfiltration attempts (asking the model to leak system prompt or credentials)

Automated harnesses: garak, Inspect Red-Team, Meta's Llama-Guard-4 as a content classifier layer.

11.5 Observability

A production agent call can fan out to tens of LLM calls, tool calls, and retrievals. Without traces you are blind. Instrument every call with:

  • Correlation ID so all spans of one request can be stitched together.
  • Input and output tokens per span (cost attribution).
  • Latency per span.
  • Verdict (success / error / tool-call) — makes aggregate dashboards trivial.

11.6 Guardrails

Guardrails live on both sides of the model:

  • Input filters. Strip or flag PII, block known-malicious patterns, language detect.
  • Output validators. Re-parse structured output against a schema, re-run if invalid.
  • Content policies. Dedicated classifier (Llama-Guard-4, NeMo Guardrails) to catch unsafe outputs.
  • Grounding checks. For RAG: verify every claim in the answer is supported by retrieved chunks.
# Guardrails sandwich — input filter, model, output validator
def safe_chat(user):
    if pii_detected(user) or injection_detected(user):
        return "Refused: sensitive input"
    raw = model.chat(user)
    if not schema.validate(raw):
        raw = model.chat(user + "\n\nReply as valid JSON only.")
    if unsafe(raw):
        return "Refused: unsafe output"
    return raw

11.7 Cost Management

  • Prompt caching (Ch 04) — often a 2–5× cost reduction on agent loops.
  • Model routing. Easy tasks to Haiku-class / local; hard tasks to Opus-class. A small router model pays for itself.
  • Streaming — cost the same, but perceived latency drops dramatically.
  • Batch mode — 50% off at Anthropic/OpenAI for non-interactive jobs.
  • Hard budgets. A per-request cap and a per-agent-run cap. Always.

11.8 Deployment — A/B, Shadow, Rollback

Treat a new prompt like a new binary:

  1. Shadow — run the new prompt alongside the old, compare outputs, don't serve users yet.
  2. Canary — 1% of traffic, then 10%, then 50%. Watch evals + error rates.
  3. Rollback — keep the old prompt and old model pinned. Revert in one switch.
  4. Version your prompts. Git-commit them. Tag them. Log which version served each request.
