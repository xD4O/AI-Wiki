Agent Architectures

8.1 ReAct — the Default

ReAct (Yao et al., 2022) is the think → act → observe loop from Chapter 01. It's the default for a reason: it's simple, it composes with every tool-calling model, and it handles 80% of agentic tasks.

def react(goal, tools, max_steps=15):
    history = [{"role": "user", "content": goal}]
    for _ in range(max_steps):
        r = llm(history, tools=tools)
        history.append(r)
        if not r.tool_calls:
            return r.text
        for call in r.tool_calls:
            history.append({"role": "tool", "content": run(call)})

8.2 Plan-and-Execute

When the plan is stable — the sequence of steps is mostly determined by the task, not by what you find along the way — ReAct wastes tokens re-deciding at every step. Separate the planner (one big upfront call that produces a JSON plan) from the executor (cheap per-step calls that follow the plan).

plan = planner.plan(goal)          # ["fetch X", "normalize Y", "plot Z"]
for step in plan:
    executor.run(step)

Plan-and-execute is faster and cheaper when the plan really is stable. When it's not — new information changes what should happen next — ReAct wins.

8.3 Tree of Thoughts & Search-Based

Tree of Thoughts (ToT, Yao 2023) and LATS (2023) generalize ReAct to search: at each decision, sample K candidate next-steps, evaluate each (via a value model or the LLM itself), and expand the best branches. BFS or DFS with pruning.

When to use: puzzles, code-golf, math — problems where a wrong branch is cheap to abandon and the space is small enough to explore.

When not to use: open-world tasks where "evaluating" a branch requires actually executing it.

8.4 Reflexion & Self-Critique

Reflexion (Shinn 2023): after a failed attempt, the agent writes a reflection — a natural-language note about what went wrong — and stores it in a separate "episodic memory." On retry, the reflection is injected into the prompt.

for attempt in range(max_retries):
    result = try_task(goal, episodic_memory=reflections)
    if evaluate(result):
        return result
    reflections.append(llm(f"Why did this fail? {result.trace}"))

Reflexion shines on tasks with cheap verifiers (unit tests, compile checks) — use the verifier's signal to drive the loop.

8.5 Router Agents

A router is an L0 orchestrator: a small, cheap model classifies the user's intent and dispatches to a specialized downstream pipeline (RAG over wiki, SQL generation, code review, …). Each downstream is optimised independently — one has RAG, one has a fine-tuned model, one calls an external API. The router is usually a 7B classifier or a rule.

Five of the most common agent patterns. All are variations of the basic loop.

8.6 Long-Horizon Agents

For tasks that run over hours (or come back tomorrow), the context window is not enough. You need:

  • Episodic memory. A store of past task traces the agent can retrieve (chapter 05).
  • Semantic memory. Facts and preferences learned over time (mem0, Letta).
  • Journaling. The agent periodically writes a structured summary of progress to disk.
  • Checkpointing. Save state so you can resume without replaying everything.

8.8 Decision Tree

  1. Does the task have a cheap verifier (unit test, compile check, grader)? → Reflexion.
  2. Is the plan stable regardless of intermediate outputs? → Plan-and-execute.
  3. Is the search space small and enumerable? → ToT/LATS.
  4. Is the intent space fixed but intermediate behavior wildly different? → Router.
  5. Otherwise → ReAct, with long-horizon patterns if it exceeds one context window.
