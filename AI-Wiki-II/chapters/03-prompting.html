CHAPTER 03 Part I · Using Models

The Art of Prompting

A principled approach to prompting — not cargo-culted tricks. Think of a prompt as a lens that picks a region of the model's distribution.

3.1 Why Prompts Matter: The Lens Metaphor

A language model is a probability distribution over next tokens conditioned on the input. The prompt is the condition — it doesn't change the model, it picks a region of the model's distribution. Good prompts make the right region sharp; bad prompts make it flat.

The model doesn't change. The prompt selects which region of its output distribution is sharp.

3.2 Anatomy of a Good Prompt

A robust prompt has six parts. You don't always need all six, but when things go wrong it's usually because one is missing.

PartWhat it doesExample
RoleNarrows the persona / style"You are a senior SRE reviewing an incident postmortem."
TaskWhat to produce"Identify root cause and list three follow-ups."
ConstraintsLength, format, tone"≤ 200 words, markdown bullets, no emoji."
ExamplesCanonical input→output pairsTwo solved incidents in the same format
FormatHow to serialize the answerJSON schema, XML tags, section headers
Edge casesWhat to do when input is weird"If the log is empty, reply with UNKNOWN."
 
PROMPT = """You are a senior SRE reviewing postmortems.

TASK
Given an incident log, identify the root cause and list three follow-ups.

CONSTRAINTS
- Reply in markdown.
- 200 words max.
- Use the headings `## Root cause` and `## Follow-ups`.
- If the log contains no timestamps, reply with `UNKNOWN`.

EXAMPLE
Input:
  2024-01-12 09:32 DB timeout on orders-db...
Output:
  ## Root cause
  Connection pool exhausted under burst traffic.
  ## Follow-ups
  - Raise pool size from 50 → 200.
  - Add p99 latency alert at 500ms.
  - Schedule load test before next launch.

NOW PROCESS
{log}
"""

3.3 Zero-shot, Few-shot, CoT, Self-Consistency

TechniqueWhen to useCost
Zero-shotTask is in-distribution — the model "gets it"Cheapest
Few-shotTask needs a specific format or style; examples pin itLonger prompt, one call
Chain-of-ThoughtMulti-step reasoning; let the model "think out loud"More output tokens
Self-consistencyHigh-stakes tasks where a wrong answer is worse than latencyN× sampling
 
# Self-consistency in 10 lines
from collections import Counter

def self_consistent(prompt, n=5):
    answers = [client.chat(prompt, temperature=0.7) for _ in range(n)]
    # pull the final answer from each rollout (adapt to your schema)
    finals = [a.split("Answer:")[-1].strip() for a in answers]
    return Counter(finals).most_common(1)[0][0]

3.4 Structured Output

Unstructured prose is nearly useless for downstream code. Three ways to get machine-parseable output from a model:

JSON mode / Structured output

from pydantic import BaseModel

class Ticket(BaseModel):
    severity: str  # "p0" | "p1" | "p2"
    summary: str
    owner: str

# OpenAI SDK
r = client.chat.completions.parse(
    model="gpt-4o",
    messages=[{"role": "user", "content": "triage: 'db is down!'"}],
    response_format=Ticket,
)
ticket: Ticket = r.choices[0].message.parsed

XML-tagged sections (Anthropic idiom)

PROMPT = """Summarise the document.

<document>
{doc}
</document>

Return:
<summary>one paragraph</summary>
<key_facts>bulleted list</key_facts>"""

Response prefilling

# Start the model's response for it — guarantees JSON
r = client.messages.create(
    model="claude-opus-4-7",
    max_tokens=1024,
    messages=[
        {"role": "user", "content": "extract name and age as JSON"},
        {"role": "assistant", "content": "{"},
    ],
)
data = "{" + r.content[0].text  # prepend the opening brace back

3.5 Anti-Patterns

"Don't hallucinate" is a negative constraint

Models are bad at negation. "Don't make up citations" plants the very word you're trying to avoid. Instead: "If you are not certain a source exists, reply 'source unknown.'" — that's a positive, verifiable rule.

  • Over-specifying. Every sentence you add narrows the lens — but also adds chance of contradiction.
  • Double negatives. "Make sure not to avoid brevity" — just say "be brief."
  • Contradictory instructions. "Be thorough but concise" is picked at random.
  • Cargo-culted phrases. "Take a deep breath" helped GPT-3.5. Current frontier models are trained past it.
  • Mixing many tasks. Ask for a summary or a classification, not both in one turn — chain them instead.

3.7 Prompting Reasoning Models

Reasoning models (Claude with extended thinking, DeepSeek-R1, QwQ-32B, OpenAI's o-series) are a different animal. Traditional CoT prompting hurts them — they've been RL-trained to reason natively, and your scaffolding conflicts with their learned process.

Rules of thumb for reasoning models
  • State the problem. State the goal. Stop there.
  • No "think step by step" — they already do.
  • No elaborate few-shot chains — show the output format, not the reasoning.
  • Ask them to verify their own answer at the end if stakes are high.
  • Budget tokens generously — they spend 5–50× more on hidden thinking.
